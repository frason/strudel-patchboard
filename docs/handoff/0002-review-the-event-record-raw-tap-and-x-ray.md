### Findings

1. **[P1] Hap fragments become extra attacks.** [observed] — `src/events.js:44–51`, `src/events.js:60`.
   - What: `recordFromHaps` copies every hap's `whole`, discards `part`, and `onsets` then treats every non-carry hap as an onset. In real Strudel, `$: note("c3").velocity(".2 .8")` queried over 0–1 returns two fragments, but only the first has `hasOnset() === true`. The record reports **two onsets at 0**, with velocities .2 and .8. Thus an x-ray overcounts and a capture can invent an attack that never played.
   - Why: a resolved control can split one event without retriggering it. Blind deduplication would also destroy deliberate simultaneous voices.
   - Recommendation: define an onset-event record using actual onset haps, with an explicit policy for carry-in fragments. If later control segments are needed, retain their part spans separately. Add this adversarial fixture before Grab.

2. **[P1] “Lossless” Take conversion changes pitch, silence and duration.** [observed] — `src/events.js:68`, `src/events.js:75–95`; downstream `src/takecode.js:20–43`.
   - What: the probes below returned `lossless:true` for `note(60).gain(0)` converted to `v:0.1`, and for `note(60.4).fast(128)` converted to note 60 and duration .05 beats instead of .03125. Gain/velocity rounding and clamping are unreported. `s` and `n` are discarded without a loss entry. A carried note spanning 0–2 queried over .5–1.5 becomes an eight-beat Take with `carry:1` but still `lossless:true`.
   - Why: these are audible changes, contradicting D10's “reports every loss.” The Take emitter can additionally merge simultaneous notes and use their maximum velocity; the present report does not cover that stage. With `grid:0` it does not inspect the emitter's default 24-step grid or its overlap/section changes.
   - Recommendation: report actual conversion/emission changes, including dropped instrument/sample identity, pitch and dynamics; preserve silence. Define whether capture rebases to `span.from` (today a 2–3 selection starts at beat 8), clips or preserves carry notes, and how tails are treated. Distinguish a quantization *preview* from an applied result: `grid` currently measures a projection but returns the original unsnapped Take.

3. **[P1] The contract loses Harmonics and calls slot length a gate.** [observed/inferred] — `src/events.js:8`, `src/events.js:33–55`, `src/compile.js:679–680`, D10.
   - What: `note("c3").s("user").partials([1,.5,.25])` loses `partials`, warns once, then converts with `lossless:true`. The warning is not propagated into the Take loss report. `note("c3").clip(.2)` records `dur:[1,1]`, the whole event's cycle slot; it is not the effective clipped sounding gate. The converter emits four beats and reports clip as lost.
   - Recommendation: narrowly preserve bounded JSON arrays needed by supported controls, including Harmonics, without admitting functions or arbitrary objects. Carry warnings/loss state through conversions. Name the stored duration honestly and define effective gate versus slot and release; inspect/replay that distinction instead of promising audible equivalence. Validate finite ranges and safe rational integers: `pair` also converts BigInts to potentially inexact Numbers, contrary to its unconditional “exact” comment.

4. **[P1] A cable-driven master survives the “neutral Output.”** [observed] — `src/compile.js:807–815` and `src/compile.js:772–778`.
   - What: connect a Slider (value .25, range 0–1) to Output volume and tap the Instrument. The returned code includes `all(x => x.postgain(slider(0.25, 0, 1)))`, yet `outside.master` is false when Output's stored volume is 1. Resetting scalar parameters leaves their parameter wires attached.
   - Recommendation: neutralize master parameter inputs as well as scalar settings in the tap copy, while retaining tempo/meter deliberately. Include wired controls when reporting outside context. Add a real-Strudel parity fixture for this exact case.

5. **[P2] Outside-context labels can be incomplete or permanently stale.** [observed/inferred] — `src/compile.js:802–817`, `src/xray.js:68–79`.
   - What: a tapped Orbit 2 with a separate reverb branch on Orbit 2 returns `orbit:false`, no downstream nodes, and the UI can say “Nothing comes after this module.” Shared-bus dependencies are not graph descendants. Separately, inserting a Filter downstream of a pinned Instrument leaves its tap code unchanged but changes `outside.downstream`; `refresh` returns on the code key before updating that explanation.
   - Checks that behaved as a raw tap should: Arrange is named downstream; tapping Arrange itself includes its sections. A Duck lead names Duck outside, and tapping Duck includes both lead and trigger. Mixer solo is ignored before the Mixer and applied at its output. A muted upstream Note Pattern stays silent. These are event/code checks, not auditions.
   - Recommendation: separate cheap annotation refresh from cached event queries, and describe shared orbit peers/duck relationships explicitly. State raw versus final semantics at the tapped location; a tap at Duck includes its routing, while a tap before it excludes it. Do not present contextual final-voice capture as implemented.

6. **[P2] Slider isolation is improved, but context is descriptive and initialization escapes the lock.** [observed/inferred] — `src/snapshot.js:13–29`, `src/snapshot.js:35–46`, `src/snapshot.js:59–60`.
