### Answers to the five direct questions

**Q1. Can below-5,000 boards still compile expensively, or normal boards be refused? Yes to both.** Finding 4 has a valid 513-cost shared board generating 3.85 MB and spending ~194 ms before refusal, plus an inactive-branch false refusal. The seven real-song fixture imports all pass with costs 2–27. The limit fixes the old exponential bomb; it is not a byte/time bound or an exact compiler-work count. No billion-writing or OOM case was executed.

**Q2. Can len leave a wrong-length loop?** Direct add/compile and valid share round-trip now preserve the tested trailing rest. **Earlier takes restoration does not** (finding 1). Full-graph Undo preserves it. Old graphs without len clean to 0 and retain their old no-padding policy; that cannot recover historical silence that was never stored. Hand edits retaining len behave as a minimum loop length: keeping silence after deleting an end note is not automatically wrong, but the length needs to be visible/editable. For the tested padded Take's generated comment, import falls back to Melody/Slow/Instrument modules rather than recreating a Take, **preserving its one-attack/two-cycle music**. readTake does not pass len into its regeneration test (`src/importer.js:263–267`); this is lost Take identity, not observed timing corruption. Saved JSON retains current len; I did not exhaust every named-save/history variant.

**Q3. Can reads start automatically while playing, or old results remain?** The normal already-playing-open behaviour is fixed and browser-verified for Grab, Bake and map. The delayed stopped → playing Grab case still starts automatically (finding 2). A request queued while stopped also needs a turn-time check. The x-ray **still intentionally performs automatic reads** on open/update under its old probe/gap policy; D15 does not claim that owner decision was resolved. A changed map range retains the old picture/text under an explicit “Press Read” prompt; label it with its actual last-read range. Invalidation for a map opened stopped is not installed consistently across later playback changes. I did not measure a new dense browser deadline miss in this review; the quiet manual sequence had none.

**Q4. Is the stricter label fair or can fine boards fail?** Its successful predicate is now a defensible **finite complete event-record equality** check (fractional start/slot, controls with its nine-place numeric comparison and pitch spelling normalization). The original false positives are gone. It can reject benign default removal (finding 7), so failed equality should describe the record difference and avoid claiming an audible change. Missing samples/listening remain correctly excluded. This is not a proof for all cycles, all control fragments or all sound semantics.

- D15(5) and F8's “starts notes”/incomplete data/omitted count are supported. The promised orange outline is not reliably visible (finding 6). The per-map budget remains explicitly deferred.

D14/D15's requirement for review/ingestion before “finished” is appropriate. I would not close the batch solely because these original regression tests pass.
